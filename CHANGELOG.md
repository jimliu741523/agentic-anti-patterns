- **AP-35 Long-horizon tool-attack chain (sequential stealth exploitation)** added — anchored to RP-6 (agent runtime guard, path-state tracking dimension). A multi-step adversarial sequence distributes its attack payload across N tool outputs — each individually passes per-step safety checks — so the cumulative trajectory achieves privilege escalation, data exfiltration, or policy override that no single-step analysis detects. Empirical anchor: arxiv 2605.03228 "MAGE: Safeguarding LLM Agents against Long-Horizon Threats via Shadow Memory" (May 2026) — shadow memory that distills the safety-critical execution trajectory and queries it pre-execution reduces sequential tool-attack-chain success from 100.0% to 8.3% and persistent indirect prompt injection to 0.0%; strongest empirical quantification to date that within-session trajectory tracking is required for long-horizon adversarial robustness. Policy-path underpinning: arxiv 2603.16586 "Runtime Governance: Policies on Paths" — compliance gates must be functions of `(agent_id, partial_path, proposed_action, state)`, not atomic per-step checks. Distinct from AP-01 (single-step injection — AP-35 payload never present in any individual output), AP-12 (cross-agent propagation — AP-35 is within-agent sequential accumulation), AP-23 (single-call argument injection — AP-35 operates at trajectory level), AP-34 (cross-session memory writes — AP-35 is within-session tool call sequences). Structural mitigation overlap: short-lived credentials (AP-26) truncate the trajectory window for AP-35 as they do for AP-34 — a shared structural fix. Four mitigations: shadow memory / trajectory tracker (pre-execution trajectory risk query), path-based policy functions `(agent_id, partial_path, proposed_action, state)`, structural credential scoping (per-session TTL truncates attack window), action-type sequence anomaly detection. Four detection signals: trajectory risk score (rising score with no individual-step alert), privilege escalation delta, action-type sequence divergence from baseline, cross-session trajectory correlation. - **AP-34 Cross-session slow-drip memory injection** added — anchored to RP-9 (MCP agent credential lifecycle, credential-lifetime amplification dimension). An adversary who can write one innocuous-seeming fragment per session to an agent's persistent memory can silently assemble a jailbreak, policy override, or false belief across 50+ sessions; each individual write passes single-session safety filters; cross-session detection rate near zero for existing defenses (arxiv 2604.21131 "Cross-Session Threats in AI Agents"). Distinct from AP-08 (single-session high-intensity poisoning — individual writes are flagged), AP-24 (agent's own unfiltered writes — no adversarial intent), and AP-30 (installation-phase supply chain — AP-34 is a runtime write-path attack distributed across sessions). Long-lived credentials amplify the attack window: binding session memory scope to credential TTL is the structural mitigation — mitigating AP-26 (shorter credential TTL, cascade revocation) directly shrinks the AP-34 accumulation window. Four mitigations: per-write source attribution with provenance history (session_id, source_attribution, monotonic counter), source contribution ceiling (>15 writes from same non-orchestrator source triggers review), semantic trajectory monitoring (centroid drift from policy-baseline snapshot), short-lived credential alignment. Four detection signals: source contribution heatmap (>10% of writes from single source), cross-session write replay (combined replay triggers what individual writes didn't), semantic drift from snapshot, per-source write-rate anomaly (>2σ above historical baseline). State/memory nav + catalog table (33→34) + code-review checklist + Roadmap updated. Cross-refs AP-08/AP-24/AP-26/AP-30. References MemoryWriter Pattern 7 + McpAgentAuth Pattern 15.
- **AP-33 Non-functional tool description bias** added — anchored to RP-8 (tool-schema wire-format incompatibility, description-sensitivity dimension). Superficial textual features of tool schema description fields — assertive cues ("RECOMMENDED", "actively maintained"), maintenance claims, usage examples — shift agent tool selection probability by 10× without changing tool functionality (arxiv 2505.18135 "Tool Preferences Unreliable," GPT-4.1 + Qwen2.5-7B; "a tool's description is entirely decoupled from its actual functionality"). Distinct from AP-09 (position/priming bias), AP-15 (description accuracy drift from behavioral change), AP-25 (format incompatibility for small models), AP-29 (invocation overhead from unconditional loading). Security surface: anyone who can edit a description field can hijack selection without changing code (same vector as AP-30 supply-chain poisoning, but structural and non-malicious origin in trusted registries). Four mitigations: description normalization layer (canonical format, marketing language stripped), behavioral usage-history grounding (task-completion-rate side-channel separate from description text), canary selection audit on registry changes (>20% shift triggers review), description-hash drift detection. Four detection signals: A/B selection audit on stripped descriptions, per-tool invocation rate drift monitoring, canary tool-pair test (neutral vs. assertive description), description assertiveness scoring. - **AP-32 Flat multi-agent memory (absent memory scope isolation)** added — anchored to RP-3 (memory write-path, multi-agent dimension). All agents write to a shared, unsegmented memory namespace with no owner, scope, or provenance isolation; a sub-agent's ephemeral working notes become retrievable institutional facts for other agents; a misbehaving agent's writes cannot be selectively revoked without treating the entire store as suspect. Distinct from AP-24 (single-agent write-ALL accumulation — AP-32 extends to N simultaneous unfiltered writers), AP-27 (physical concurrent write conflict — AP-32 is semantic scope contamination that occurs even when writes succeed without race conditions), and AP-31 (hallucinated consensus — agents don't commit state; AP-32 is the opposite: agents over-commit without governance). Evidence: arxiv 2605.04264 "Governed Collaborative Memory as Artificial Selection" (May 2026) — formally defines the multi-agent shared-memory governance gap; provenance fidelity, selection traceability, epistemic quality, and correction pathways required; no OSS package exists. arxiv 2604.16548 (mnemonic sovereignty survey) — "cross-agent memory isolation" named "sparsely studied open engineering problem." arxiv 2512.16310 — 90.24% Risk Leakage Rate in multi-tool agents (scope failures compound across agent boundaries). ossinsight.io: "every memory type needs an owner, a scope, an expiry rule, and a deletion path." Four mitigations: scoped namespaces (agent_id+task_id), provenance tagging at write time, governed promotion (orchestrator approves fact elevation to shared scope), selective rollback by agent_id. Four detection signals: write attribution coverage, cross-agent contamination probe, scope promotion audit log, rollback completeness test. ## 2026-05-10
- **AP-31 Hallucinated multi-agent consensus** added — anchored to RP-5. Distinct from AP-27 (physical state corruption from missing locks): AP-31 is about semantic-belief misalignment that produces no lock violation, no exception, and no detectable write conflict. Agents verbally report agreement or task completion without committing state to any shared store; the coordinator proceeds on the verbal signal alone and the assumed coordination never actually happened. Evidence: MAST (arxiv 2503.13657) names "hallucinated consensus" as a distinct recurring failure mode across 7 frameworks; Semantic Consensus Framework (2604.16339) achieves 100% workflow completion where natural-language-coordination baselines fail; inter-agent misalignment accounts for 36.9% of all observed failure modes (2601.04170); production failure rates 41–86.7%. Four mitigations: commit-then-announce (write state before broadcasting), quorum confirmation with store-side verification, semantic divergence check before acting on agreement (DriftMonitor), agent-authored machine-readable postconditions. Four detection signals: claimed-complete vs. committed-record invariant, semantic similarity between claimed-agreeing agents, post-phase state validation, time-to-commit invariant. System/lifecycle nav + catalog table (30→31) + Roadmap updated. Cross-refs AP-12/AP-13/AP-21/AP-27. References AgentCoord Pattern 11.
- **AP-30 MCP marketplace supply chain injection** added — anchored to RP-9. Installation-phase supply chain attack: developers or orchestrators install MCP servers from public registries without version pinning, content-hash verification, or allowlist controls; typosquatted packages, ownership-transferred servers, and registry-hijacked servers inject attacker-controlled tool descriptions into the agent's context. Escalation path: metadata poisoning → stdio RCE (CVE-2026-30623 LiteLLM command injection; CVE-2026-23744 MCPJam RCE). Evidence: OX Security April 2026 advisory (200,000+ vulnerable instances, 4 exploitation families including MCP marketplace malicious packages, Anthropic confirmed "expected behavior"); arxiv 2510.16558 (833 vulnerable servers in 67,057 scanned; weak registry vetting); vulnerablemcp.info taxonomy (6 Supply Chain CVEs, 13 RCE, 15 Data Exfiltration). Distinct from AP-16 (trust boundary collapse post-install) and AP-26 (credential blast radius post-compromise). Four mitigations: version+hash pinning, allowlist-only registry, tool-description fingerprint drift detection on startup, subprocess network egress isolation. Four detection signals: server content hash drift, tool cardinality invariant, MCP subprocess network anomaly, registry ownership change subscription. Input/ingress nav + catalog table (29→30) + code-review checklist + Roadmap updated. Cross-refs AP-01/AP-16/AP-23/AP-26.
- **AP-29 Unconditional tool invocation (tool-use tax)** added — anchored to RP-8. Agents transmit the full tool-schema catalog on every turn and invoke tools unconditionally; under semantic noise, the tool-calling protocol itself degrades reasoning quality below plain chain-of-thought even when schemas are correctly formatted. Two distinct costs: (1) per-turn schema overhead — a 40-tool catalog adds ~3,000 tokens on every turn including conversational and follow-up turns where no tool is needed; (2) quality degradation — tool-augmented reasoning underperforms CoT under semantic noise (arxiv 2605.00136 Tool-Use Tax). Distinct from AP-25 (wrong format for target model) and AP-28 (runaway cost from repeated invocation). Four mitigations: G-STEP invocation gate (per-turn semantic utility scoring), lazy schema loading (top-K relevance-ranked injection), hot/warm/cold tool tier, direct-reasoning fallback path. Four detection signals: tool-call rate by turn type, schema token overhead ratio, A/B accuracy on conversational queries, per-turn latency breakdown. Action/egress nav + catalog table (28→29) + code-review checklist + Roadmap updated. Cross-refs AP-02/AP-05/AP-09/AP-25/AP-28. References ToolSchemaCompiler Pattern 14.
