- **AP-49 Time-dependent memory coherence degradation (absent TTL/decay enforcement in long-running agents)** added — anchored to RP-3 (memory write-path filtering, contradiction handling, learned forgetting). After 24–72+ hours of operation, committed facts that were valid at write time are retrieved as authoritative without any staleness signal; retrieval ranking has no temporal discounting, so a 6-hour-old fact and a 30-second-old fact rank equally if embeddings match. arxiv 2605.03675 MemTier quantifies the production cost: **14-point tool execution success drop over 72 hours** from coherence degradation without TTL/decay enforcement; "point-in-time contradiction detection alone is insufficient." arxiv 2605.06527 STALE confirms best model achieves only **55.2% accuracy on implicit-conflict scenarios** where a stored memory and a current observation contradict without an explicit flag — confirming retrieval cannot correct for absent write-time freshness metadata. arxiv 2603.11768 SSGM formalizes "intrinsic drift" and proposes "forgetting-by-design" — naming no production-grade OSS middleware that implements scheduled decay or validity windows. arxiv 2605.02199 MEMAUDIT confirms existing stores (Mem0, A-Mem, Letta) cannot self-audit freshness or validity-state preservation under storage budgets. Distinct from AP-24 (quantity problem — accumulation without salience gating; AP-49 is temporal freshness after correct initial commit), AP-37 (probabilistic problem — overconfident belief collapse at write time; AP-49 assumes initial belief was correct), AP-39 (adversarial injection; AP-49 is structural non-adversarial staleness), AP-40 (behavioral erosion from conflict accumulation in multi-agent settings; AP-49 is single-agent tool-grounding failure from temporal drift), AP-32 (namespace isolation; AP-49 is temporal freshness — orthogonal write-path dimensions). Four mitigations: TTL-tagged write path (`expires_at` per domain — 1h API state, 24h session context, 7d preferences; retrieval layer filters before embedding search); confidence-decay weighting (`current_confidence = initial × exp(–decay_rate × elapsed_seconds)` as ranking multiplier); staleness-aware re-validation (lightweight LLM validity check before committing retrieved fact to tool call; escalate if uncertain); MEMAUDIT periodic freshness audit (alert when stale-entry fraction >15%). Four detection signals: tool-success trend by session age (slope steeper than –0.2 pp/hour = TTL degradation); retrieved-memory age distribution (median >2× domain TTL = leading indicator); contradiction rate with current-turn observations (>10% = stale entries dominant); STALE-class probe on deployed agent (<70% implicit-staleness accuracy = retrieval not filtering superseded entries). Cross-refs AP-24/AP-32/AP-37/AP-39/AP-40. Catalog: 48→49.
- **AP-48 Activation-blind tool selection (absent pre-execution selection-confidence gate)** added — anchored to RP-8 (tool-schema wire-format incompatibility / small-model tool-calling reliability). When an agent selects a tool via autoregressive generation, no runtime surfaces the model's internal selection-confidence signal to gate execution. The activation gap between competing tool-choice directions in the model's residual stream predicts errors **14–21x more accurately** on Gemma 3 12B/27B than random (arxiv 2605.07990); low-gap queries produce that many more wrong calls than high-gap queries, and JSON arguments autoregressively conform to whichever tool's schema wins — making wrong-tool calls invisible at the protocol layer (the call "succeeds" with a valid response). Separately, models encode reliable tool-necessity signals in hidden states even when they fail to act on them during generation (arxiv 2605.09252 When2Tool, 18 environments). Both mechanistic and behavioral signals are discarded before any runtime guard; no standard framework exposes either to a pre-execution gate. Distinct from AP-09 (habitual high-confidence wrong tool vs. AP-48's low-confidence competing tools), AP-25 (schema-format parse failure vs. AP-48's correct-format selection uncertainty), AP-29 (tool-call vs. CoT decision vs. AP-48's which-tool decision within a committed tool call), AP-33 (external description manipulation vs. AP-48's internal model uncertainty). Four mitigations: logit-gap pre-execution gate (measure top-1/top-2 tool-name token gap; below threshold, inject disambiguation step); Reason-then-Act invocation wrapper (structured reasoning before tool-name generation to surface necessity signal, training-free); competing-tool arbitration probe (sample second candidate, lightweight arbitration before execution); selection-confidence telemetry (log per-call logit gap, alert on 5th-percentile drop to surface AP-33/AP-25 root causes). Four detection signals: wrong-tool rate by confidence decile (>10× bottom vs. top = gate warranted); retry-invariant wrong-tool (≥2 retries, same wrong tool, no error = systematic low-confidence); high-entropy tool-name prefix tokens; When2Tool-class accuracy probe on deployed model. Cross-refs AP-09/AP-25/AP-29/AP-33. References tool-schema-compiler item (g) (selective invocation gate). Catalog: 47→48.
- **AP-47 Semantic intent divergence (cross-agent task interpretation drift without shared semantic anchor)** added — anchored to RP-5 (multi-agent concurrent state coordination primitives). When parallel agents are dispatched from a shared natural-language directive with no formal semantic commitment protocol, each independently resolves ambiguous task parameters (scope, output format, constraints, priority) from its local context. Agents produce internally coherent but semantically incompatible outputs; no standard framework provides a pre-dispatch task contract or a pre-merge semantic alignment gate. Empirical anchors: arxiv 2604.16339 "Semantic Consensus" — **79% of multi-agent failures from specification and coordination issues, not model capability**; explicitly names "Semantic Intent Divergence" as a distinct failure mode; Semantic Consensus Framework achieves **100% workflow completion** across AutoGen/CrewAI/LangGraph where baselines fail — confirms the pre-merge alignment primitive gap is real; arxiv 2601.04170 "Agent Drift" — inter-agent misalignment = 36.9% of all observed failure modes; token duplication 53–86% indicates absent semantic partitioning at dispatch; arxiv 2602.01011 "Multi-Agent Teams Hold Experts Back" — 37.6% capability loss, incommensurable output divergence is one contributing mechanism alongside integrative compromise (AP-44). Symptom: combiner receives structurally incompatible inputs and silently outputs incoherent aggregate or crashes with a type mismatch whose stack trace gives no semantic root cause; retry-invariant (structural, not transient). Distinct from AP-27 (physical write conflict — shared artifact, concurrent writes), AP-31 (hallucinated verbal consensus — false agreement, not silent divergence), AP-42 (attribution forensics — post-failure diagnosis, not pre-dispatch prevention), AP-44 (integrative compromise — quality dilution on shared objective, not incommensurable interpretations), AP-45 (phase ordering — timing failure, not semantic alignment failure). Four mitigations: pre-dispatch task contract (structured YAML/JSON: objective/scope/output_format/output_schema/constraints/priority_order); mid-execution semantic drift check (cosine similarity vs. task-contract embedding, threshold 0.70); pre-merge semantic consensus gate (pairwise intent-compatibility, re-alignment cycle on low-similarity pair); structured output schema enforcement on inter-agent handoffs (catches format drift; insufficient alone for scope drift). Four detection signals: combiner input divergence metric (mean pairwise cosine similarity < 0.65 = flag); schema mismatch count at combiner boundary; post-run semantic audit (output vs. directive distance > 0.4 = scope drift); retry-invariant combiner failure (3+ retries same outputs = semantic root, not transient). Cross-refs AP-27/AP-31/AP-42/AP-44/AP-45. Catalog: 46→47.
- **AP-46 Stale-claim orphan deadlock (mid-task agent failure without lease recovery)** added — anchored to RP-5 (multi-agent concurrent state coordination primitives). When a worker agent crashes, errors, or is killed after claiming a work-queue task but before releasing it, the claim remains permanently asserted; orchestrators and downstream phases block indefinitely on a completion event that never arrives. Root cause: no claim TTL, no heartbeat/lease-renewal protocol, no watchdog reassignment primitive in any agent framework. Symptom: pipeline throughput drops to zero with no exception, no cost alarm, no loop counter — the pipeline is frozen while the dead agent's record holds `status=claimed`. Empirical anchors: sigalovskinick "Mid-Task Agent Failure" (one of eight recurring failure modes in ~20k LOC custom infra); arxiv 2502.14743 (deadlock = "agents stop moving forever as if being locked," absent lock/queue/barrier primitives as root cause); TraceFix 2605.07935 (31.1% → 14.1% deadlock/livelock with formal verification — residual 14.1% is runtime crash failures that TTL/heartbeat/watchdog fill); arxiv 2605.03310 (41–87% production failure rates from coordination defects as causal root). Distinct from AP-27 (write conflicts — parallel agents overwriting, not blocking), AP-31 (hallucinated consensus — false agreement, not a stuck claim), AP-36 (saturation cascade — downstream overloaded, not upstream dead), AP-42 (attribution forensics — post-failure diagnosis, not live freeze), AP-45 (phase ordering — phase N+1 advancing too early, not phase N never finishing). Four mitigations: TTL-bearing claim leases with background auto-expiry; heartbeat-based lease renewal (`lease.renew()` at `ttl/3` intervals); orchestrator watchdog with claim reassignment on stale heartbeat; DEGRADED pipeline state propagation on `max_attempts` exhaustion. Four detection signals: claim-age histogram (>3× median with no heartbeat = orphan alert); work-queue drain stall (in-progress items, no completions, no advancing heartbeats); agent-ID liveness cross-reference (process absent but claim live = immediate reassignment); attempt-count anomaly (≥2 re-queues without completion). Cross-refs AP-27/AP-31/AP-36/AP-42/AP-45. References AgentCoord Pattern 11 (`WorkQueue.claim(ttl_secs)` + `CrashRecovery` components). Catalog: 45→46.
- **AP-45 Absent phase-gate barrier (parallel agents advancing without inter-phase synchronization)** added — anchored to RP-5 (multi-agent concurrent state coordination primitives). Parallel agent pipelines lacking an explicit inter-phase barrier allow phase N+1 agents to consume incomplete or partial outputs from phase N; no standard framework provides a `Barrier(n_agents)` primitive. Practitioners substitute wall-clock sleep or item-count polling — neither guarantees all phase-N agents have committed; a crashed agent leaves its slot empty and count-based checks still fire at N-1. Empirical anchors: arxiv 2502.14743 (barrier primitives explicitly named as missing across all surveyed frameworks); TraceFix 2605.07935 (deadlock/livelock from 31.1% to 14.1% with formal protocols — 14.1% residual is runtime gap that barrier primitives fill); LATTE 2605.06320 (formal Claim/Complete/Release operators assume underlying barrier substrate not provided by any Python library); MAST 2503.13657 (most multi-agent failures at system boundaries, not individual model calls). Practitioner anchor: sigalovskinick ~20k LOC custom infra documenting "Flat Task Lists (no phase gates)" as one of eight recurring failure modes. Four mitigations: explicit `Barrier(n_agents, phase_id)` with SQLite backing; output manifest before barrier.arrive (barrier blocks until all manifested keys confirmed on disk); crash-recovery watchdog for stale leases; phase commit tokens for stale-write rejection. Four detection signals: phase advancement timestamp ordering (`phase_N1_first_start < phase_N_last_arrive` = violation); output completeness audit (read count < n_agents = barrier absent); crash-incomplete rate above 0% without DEGRADED flag; aggregator input count vs. expected. Distinct from AP-27 (concurrent within-phase write conflict — same-phase parallel overwrites), AP-36 (throughput collapse from saturation — AP-45 is correctness failure from premature advancement), AP-31 (false agreement signal — AP-45 is incomplete real input), AP-42 (post-failure forensics — AP-45 is prevention). Cross-refs AP-27/AP-31/AP-36/AP-42/AP-44. References AgentCoord Pattern 11 (`Barrier` component, mitigations 1 and 3). Catalog: 44→45.

## 2026-05-12
- **AP-44 Expert-blind team averaging (expertise dilution under integrative compromise)** added — anchored to RP-5 (multi-agent concurrent state coordination primitives). Multi-agent LLM teams consistently perform worse than their best single member — up to 37.6% capability loss (arxiv 2602.01011 "Multi-Agent Teams Hold Experts Back") — because no coordination primitive exists to route final decisions to the most capable agent for each subtask type. Teams default to averaging or majority-voting that dilutes specialist knowledge. Root cause: capability not tracked per agent per task type at runtime; dissenting minority expert opinions suppressed by consensus-seeking protocols. Distinct from AP-27 (physical write conflicts), AP-31 (false verbal agreement), AP-36 (capacity saturation), AP-42 (post-failure attribution). Four mitigations: per-agent task-type EMA performance profile, expertise-weighted voting, dissent-preservation protocol (minority recommendation surfaced before consensus), DriftMonitor-based dynamic role assignment. Four detection signals: team vs. best-member accuracy delta (>5% = integrative compression), expert-suppression rate (>30% = systematic dilution), capability profile staleness, fast consensus on difficult subtasks (red flag). Cross-refs AP-27/AP-31/AP-36/AP-42. References AgentCoord Pattern 11 (DriftMonitor for mitigation 4).
- **AP-43 Coarse-grained tool authorization (binary allow/deny without per-call scope enforcement)** added — anchored to RP-6 (agent runtime guard, per-tool authorization dimension). Agent runtimes authorize tools as binary enabled-or-disabled at configuration time; every call to an enabled tool is automatically passed with no per-call check of caller identity, session scope, required privilege, or action intent. Production deployments require ALLOW/DENY/MODIFY/DEFER/STEP_UP verdict granularity that no current framework provides as composable middleware. Empirical anchors: GitHub openai-agents-python#2868 (practitioners explicitly requesting non-binary per-tool authorization middleware — ALLOW/DENY/MODIFY/DEFER/STEP_UP — April 2026, open); arxiv 2605.04785 AgentTrust (first released pre-execution interception, 95.0–96.7% verdict accuracy, AGPL, content/command safety only — confirms interception architecture works, leaves MIT/Apache per-call authorization gap open); arxiv 2605.02682 CASA (hybrid task-based access control research, no package); arxiv 2604.16706 AgentProp-Bench (rejection and recovery are independent capabilities, rho=0.126 — binary tool blocking cannot substitute for structured per-call authorization). Distinct from AP-23 (argument-boundary injection — AP-43 is the authorization decision before args are inspected), AP-41 (return-content injection — AP-43 fires before execution, AP-41 fires after), AP-26 (credential blast radius — AP-43 is about tool-call scope, not credential lifecycle).
- **AP-42 Multi-agent failure attribution blackout** added — anchored to RP-5 (multi-agent concurrent state coordination primitives). When a multi-agent pipeline produces wrong output or crashes, no runtime mechanism identifies which agent or step was responsible; teams restart the full pipeline rather than rolling back to the earliest faulty step. Empirical anchors: arxiv 2604.22708 (attribution unsolved in partially-observable traces); MASPrism 2605.07509 (0.6B probe model achieving 89.50% relative improvement over Gemini-2.5-Pro on attribution accuracy); Conformal Agent Error Attribution 2605.06788 (certifiable finite-sample rollback targets via conformal prediction). Key distinction from AP-27 (concurrent state corruption) and AP-31 (hallucinated consensus): AP-42 is the diagnostic failure — wrong output propagated through sequential handoffs with no provenance trail — not a concurrent write conflict or false agreement.
- **AP-41 Tool-return content injection (trusted-channel indirect injection)** added — anchored to RP-6 (agent runtime guard, return-content sanitization dimension). Adversaries embed malicious instructions in a registered tool's *response content* — API response body, database record field, MCP tool output payload, file read result — which the agent incorporates into conversation history as a trusted first-party observation with no data-boundary sanitization applied. Key distinction from AP-01 (direct prompt injection): AP-41 exploits the elevated trust agents place on registered-tool outputs — no `<external_data>` markers or dual-LLM sanitization is applied to structured tool return values. Empirical anchor: arxiv 2604.11790 ClawGuard. Confirmed by AgentTrust (2605.04785) and Reinforced Agent (2604.27233).
- **AP-40 Cooperative intent erosion from unbounded memory accumulation (Memory Curse)** added — anchored to RP-3. Expanding accessible history without write-path content governance degrades multi-agent cooperation in 18/28 model-game settings (arxiv 2605.08060). Memory content (conflict history), not length, is the causal trigger; write-path content filtering restores cooperation substantially.
